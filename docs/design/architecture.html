AI Robot Redesign Engine: agent architecture

Centralized orchestrator-workers with a Tiger Data blackboard and a code-built case, tightly scoped advocates, one writer and a Decision 1 critic. Hack Western 13 design v3.2.

Why centralized orchestrator-workers

  • • Part lookups are decomposable and parallel: the case where multi-agent wins (+80.8% on decomposable tasks, Kim et al. 2025).
  • • Central verification contains error spread: 4.4x vs 17.2x for independent agents (same paper).
  • • Lead + parallel subagents with effort budgets: Anthropic research system pattern.

Blackboard rules

  • • Workers share supplier facts, blocked sites and hints, not transcripts.
  • • Append-only rows; only the Verifier writes kind=fact.
  • • Site status lives only in agent_runs; the orchestrator's circuit breaker sees every outcome first-hand.
  • • TinyFish runs cannot read the board mid-run; workers read it between dispatches and put it in the next goal.

Synthesis rules

  • • Ranking, strengths and weaknesses are computed in code; verdicts never change here.
  • • Advocates only choose and phrase items from their design's case lists, cite claim ids, write no numbers.
  • • One cross-exam round; rebuttals must target a weakness code already listed.
  • • Decision 1 rubric gates the drafts; gaps go back to the orchestrator once.
