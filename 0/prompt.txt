- **`Project`** (`schemas.py:374-390`): `id`, `kind` ("company"|"club"), `name`, `robot`, `use_case`, `robot_kind` ("wheeled"|"arm"), `arm: ArmParams|None`, `wheeled: RobotRequirements|None`, `deep_line`, `deep_frame` (default "23"), `cad_robot: Literal["wheeled","ar4","stretch"]` (default "wheeled"), `bom: list[BomLine]`, `intake_sources`, `stated: ProjectFacts`.
- **`ArmParams`** (`schemas.py:336-350`): `joint`, `payload_kg`, `reach_m`, `links[{name, mass_kg, com_m}]`, `gear_ratio`, `efficiency`, `omega_max_dps`, `t_accel_s`, `safety_factor` (1.5), `bus_voltage_v`, `illustrative`, `notes`.
- **`BomLine`** (`schemas.py:353-371`): `sources: list[str]` (URLs behind price and origin), alongside `id, domain, qty, part, manufacturer, part_number, unit_price_usd, origin_country, origin_tier, availability, lead_time_days, hts_code, component_class, illustrative, notes`.
- **`ar4_club`**: club, `deep_line="j2_motor"`, one BOM line, no intake sources, `stated` = CA / $2500 / 21 days, `cad_robot="ar4"`, `deep_frame` left at the default "23".
- **`stretch`**: company, illustrative arm, `deep_line="shoulder_motor"`, 4 BOM lines, 4 intake sources, `deep_frame="34"`, `cad_robot="stretch"`.

**How a `project_id` changes the pipeline** (`orchestrator/job.py:40-56`):
- `intake` (`intake_stages.py:29`) returns early when there's no project or no `intake_sources`. That means it does nothing for ar4_club.
- `criteria` (`:84`) and `risk_baseline` / `alternatives` / `recommend_lines` (`risk_stages.py:23,40,86`) all skip when there is no project.
- `compliance_baseline` runs only when there is no project (`job.py:60-61`).
- `plan_queries(ctx.project)` (`job.py:66`), `requirement_for(robot, project)` (`job.py:185`), and `baseline_frame` / `baseline_names` (`job.py:249-260`) all depend on the project.
- REPORT has no handler.

**What `cad_robot="stretch"` does today:** `cad_robot()` (`job.py:244-246`) sends `robot="stretch"` to the worker. The worker's `BuildRequest.robot` only accepts `"wheeled"|"ar4"`, so it answers 422. `CadClient` turns that into `CadError("CAD build … failed: HTTP 422 …")` (`cad_client.py:78-79`). That error is emitted as a non-fatal error event in CHECK (`job.py:200-202`, fit goes to Review) and in BUILD (`job.py:271-273`, no baseline design and no candidate `design_ready` events). Separately, `generic_fit` is set to True because the robot isn't "wheeled" (`job.py:204`).

## 8. Price verification

- **Teknic goal** (`agents/targets.py:60-63`): "quote = the row label and the value exactly as they appear… Do not add colons, words or labels that are not on the page… For price, quote the price text exactly as displayed (e.g. "$293")."
- **Check** (`verifier.py:84-90`): the claim passes only if the normalized quote is a substring of the normalized page. Normalizing removes tags, colons and thousands separators, collapses whitespace and lowercases.

Why a quote like "Price $265.00" can fail (from the code; I didn't check the live page):
- The word "Price" may have been added by the agent and not appear next to the amount on the page.
- The page may render "$" and the number with a space between them, or show "$265" instead of "$265.00".
- The price may be filled in by JavaScript, so it is missing from both fresh fetch passes (`VERIFY_PASSES`, `job.py:84`). The last fallback, `verify_on_agent_snapshot` (`job.py:135-159`), only helps if:
  - the claim has a `source.run_id`,
  - a step's canonical URL passes `same_page()` against the claim's URL (the model page, with the selected voltage),
  - that step's HTML exists.
  
  It checks only the most recent matching step and then stops (`break`), so a snapshot taken before the price loaded fails too.
- In replay, `run_steps`, `step_canonical` and `step_html` must each have a recording, or the job raises `ReplayMiss`.
